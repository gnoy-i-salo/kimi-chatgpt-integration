# Архитектура

Источник истины зависимостей — `architecture/workspace.c4`. Сейчас в модели только обзорный элемент `workspace`; он не обозначает npm-пакет. Каждому будущему workspace соответствует один `module` с точными `package` и `path` в metadata.

Внутренние зависимости объявляются как `workspace:*` и моделируются связью `imports`. Проверка отвергает неизвестные пакеты, расхождения модели и manifests, циклы, deep imports, относительные выходы за границы пакета и self-import через собственный публичный API. Для внешних импортов требуется зависимость в manifest владельца. Тестовые Vitest/Playwright imports используют корневые инструменты.

`packages/*` содержит общие модули; `apps/*` — приложения. Все npm-пакеты приватные, namespace — `@kimi-chatgpt-integration/*`, пути — kebab-case. Каждый пакет имеет `src/`, `build` и `typecheck`.

Приложения следуют FSD: `app → pages → widgets → features → entities → shared`. Разрешено пропускать нижние слои; запрещены импорты вверх и между слайсами одного слоя. Другие слайсы доступны через публичный `index.ts`. `app` и `shared` не делятся на слайсы. Entrypoint `main.ts(x)` импортирует только `app`.

`index.ts` содержит только явные реэкспорты, включая `export type`. Реализация принадлежит отдельным модулям. Внутри пакета используются относительные импорты.

Сценарии и состояние UI принадлежат `model` слайса. Адаптеры транспорта, native IPC и хранения размещаются в `shared/api`. UI обращается к ним через model: проверка запрещает прямые runtime imports из `shared/api` и `@tauri-apps/*` в каталогах `ui/`, включая dynamic import/require. Явные `import type` разрешены. Дополнительные продуктовые границы вводятся вместе с отрицательными fixtures.
